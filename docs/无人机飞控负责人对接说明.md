# 无人机巡查项目——飞控负责人/AI 对接说明

> 本文可直接交给负责无人机、飞控、电机和电调的同学，也可以原样作为 AI 的项目上下文和任务说明。请先完整阅读，再连接或驱动任何硬件。

## 1. 项目目标

使用多旋翼无人机自主巡查 `450 cm × 350 cm` 区域。场地划分为 `9 × 7`、共 63 个 `50 cm × 50 cm` 方格。

任务要求：

1. 从地图右下角红色区域 `A9B1` 起飞。
2. 飞行高度保持 `1.20 m ± 0.10 m`。
3. 只能沿方格上下或左右飞行，不能从一个格子斜飞到另一个格子。
4. 不得进入或飞越现场给出的禁飞方格。
5. 覆盖所有非禁飞方格，最后返回 `A9B1` 并降落。
6. 每到一个新方格，稳定后触发一次动物识别；不要按视频帧不断累计同一目标。
7. 总任务时间不超过 300 秒。
8. 无人机下方激光笔垂直指示航线。

动物类别固定为：

```text
elephant  象
tiger     虎
wolf      狼
monkey    猴
kongque   孔雀
```

注意：模型内部使用 `kongque`，不要擅自改成 `peacock`，否则会与现有识别和 UI 统计不一致。

## 3. 当前已经完成的功能

以下功能已经存在，不需要飞控负责人重复开发：

1. 地面站选择禁飞格并发送到 NX。
2. 9×7 网格覆盖航线规划。
3. 内部覆盖路线只使用四邻域移动；发布时只压缩同一直线上的中间点，不生成斜线段。
4. 航线避开禁飞格，从 `A9B1` 出发并回到 `A9B1`。
5. 航线通过 `/mission/global_path` 发布，类型为 `nav_msgs/Path`，坐标系为 `mission`。
6. 默认每个航点 `z=0`；飞行执行器统一使用 `takeoff_height=1.2 m`，网格中心间距为 `0.5 m`。
7. 机载路径接收器能进行基本合法性检查并发布回执。
8. TensorRT YOLO 已能识别五类动物。
9. 按格识别状态机已经完成，可以根据 `/current_grid` 每格统计一次。
10. 地面站目标页面能显示五类动物的方格和数量，并保存 CSV。
11. 点击 UI 的“启动识别”会发布任务 `START`，摄像头和 YOLO 启动节点会收到该命令。

必须特别注意：

- 现有 `/planner/path_ack` 只说明路径格式通过检查，不表示无人机已经能执行路径。
- 当前没有代码控制飞控解锁、起飞、位置设定、返航或降落。
- 当前没有代码控制电机、电调或激光笔。
- 不要把“路径已经收到”误判为“整机已经具备自主飞行能力”。

## 4. 当前坐标系和格子换算

规划路径的 `frame_id` 固定为：

```text
mission
```

以任务开始时的 `A9B1` 方格中心为 `mission` 固定坐标系原点：

```text
A9B1 -> x=0.0, y=0.0
B 增大 -> x 增大
A 减小 -> y 增大
```

格子到路径坐标：

```text
x = (B - 1) × 0.5
y = (9 - A) × 0.5
z = 0.0
```

路径坐标反算格子：

```text
A = 9 - round(y / 0.5)
B = round(x / 0.5) + 1
```

例如：

```text
A9B1 -> (0.0, 0.0, 0.0)
A9B2 -> (0.5, 0.0, 0.0)
A8B1 -> (0.0, 0.5, 0.0)
A1B7 -> (3.0, 4.0, 0.0)
```

这里的坐标是方格中心之间的距离，所以中心范围是 `3.0 m × 4.0 m`；把方格的半格边界计入后，实际覆盖区域仍是 `3.5 m × 4.5 m`，只是相对于题目 `4.5 m × 3.5 m` 的描述旋转了 90°。

飞控负责人必须在现场完成 `mission` 与飞控本地坐标系的对齐：

1. 无人机放在 `A9B1` 中心时，将该点定义为 `(0,0)`。
2. 飞向 `B2` 的方向必须是本地 `+x`。
3. 飞向 `A8` 的方向必须是本地 `+y`。
4. 起飞前检查航向角，不能仅仅假定机头朝向正确。
5. 如果飞控的 ENU/NED 或机体系方向不同，必须通过 TF 或执行节点显式转换，不能靠交换数字碰运气。

## 5. ROS 接口合同

### 5.1 地面站禁飞区

```text
话题：/mission/forbidden_zones
类型：nuedc_ground_air/ForbiddenZones
发布者：landscreen_ros1_bridge
订阅者：ground_path_planner；飞行执行器建议同时订阅用于二次安全校验
```

消息定义：

```text
Header header
int32 f1x
int32 f1y
int32 f2x
int32 f2y
int32 f3x
int32 f3y
bool launch
```

`f1x/f1y` 表示 A/B 编号，而不是米制坐标。无效空项为 `-1,-1`。

当前 UI 和消息最多表达 3 个独立禁飞格。如果正式比赛可能给出超过 3 个禁飞格，必须提前通知地面站开发人员扩展为数组；飞控端不能假装忽略多余禁飞格。

### 5.2 规划路径

```text
话题：/mission/global_path
类型：nav_msgs/Path
发布者：ground_path_planner
关键属性：header.frame_id == "mission"；latch=true
```

每个 `PoseStamped`：

- `position.x/y`：相对任务起点的固定坐标，单位 m。
- `position.z`：默认 `global_path_use_pose_z=false`，因此为 `0`；执行端统一采用 `takeoff_height=1.2 m`。只有显式打开该参数时，路径 z 才写入起飞高度。
- `orientation`：所有点均为单位四元数 `(0,0,0,1)`，路径不要求机身改变航向，执行端按平移方式运行。
- 发布路径默认压缩同一直线上的中间格点，因此相邻 `PoseStamped` 可能跨越多个 `0.5 m` 方格，但必须满足 x 或 y 只有一个轴变化。执行端应沿该轴直线运行，并按每 `0.5 m` 重建经过的中间格，不能斜切转角或禁飞格。
- 第一个和最后一个点都应为 `A9B1=(0,0,0)`。

路径格式回执：

```text
话题：/planner/path_ack
类型：std_msgs/String
数据：JSON
示例：{"accepted":true,"points":25,"frame_id":"mission","reason":"ok"}
```

这个回执仅验证非空、点数、有限坐标和 `frame_id`，不是飞控执行确认。

### 5.3 任务命令

```text
话题：/mission/command
类型：nuedc_ground_air/MissionCommand
发布者：landscreen_ros1_bridge
订阅者：视觉启动节点、按格识别状态机；未来飞行执行器也应订阅
```

消息定义：

```text
Header header
string command
float32 target_x
float32 target_y
float32 target_z
```

当前有效命令：

```text
START
STOP
ABORT
```

当前 UI 点击“启动识别”后，在 `launch` 从 false 变为 true 的上升沿发布一次 `START`。`target_x/y/z` 当前没有使用。

飞行执行器不能在一收到 `/mission/global_path` 时就起飞，必须缓存路径并等待明确的 `START`。收到 `STOP/ABORT` 时应停止任务并进入预先约定的安全动作。

### 5.4 飞行执行器需要发布的当前格子

```text
话题：/current_grid
类型：std_msgs/String
发布者：未来的飞行执行器/定位到格节点
订阅者：grid_recognition_state_machine
格式：A1B1、A6B3、A9B1 等
```

推荐握手流程：

1. 无人机到达目标格中心。
2. 水平、垂直位置和速度均进入稳定阈值。
3. 发布一次该格编号，例如：

   ```bash
   rostopic pub -1 /current_grid std_msgs/String "data: 'A6B3'"
   ```

4. 按格状态机先稳定等待 `0.3 s`，再统计 `1.0 s`。
5. 飞行执行器订阅 `/vision/grid_state`，等本格状态变为 `GRID_COMPLETE` 后再去下一新格。
6. 如果路径为了连接或返航再次经过已经识别的格子，状态机会返回 `GRID_ALREADY_SCANNED`，不会重复累计。

不要在飞行过程中以高频率持续发布不断变化的格子；必须以“到达并稳定”为触发条件。

### 5.5 按格识别状态

```text
话题：/vision/grid_state
类型：std_msgs/String
数据：JSON
```

可能状态：

```text
WAIT_START
WAIT_GRID
STABILIZING
RECORDING
GRID_COMPLETE
GRID_ALREADY_SCANNED
```

示例：

```json
{"state":"GRID_COMPLETE","grid":"A6B3","detail":"recognition window completed","scanned":["A6B3"]}
```

飞行执行器解析时必须同时核对 `state` 和 `grid`，不能把上一个格子的完成消息当作当前格完成。

### 5.6 按格识别结果

```text
话题：/vision/grid_result
类型：std_msgs/String
数据：JSON
发布者：grid_recognition_state_machine
```

示例：

```json
{
  "grid":"A6B3",
  "a":6,
  "b":3,
  "counts":{
    "elephant":1,
    "tiger":0,
    "monkey":0,
    "kongque":0,
    "wolf":0
  },
  "sampled_frames":5
}
```

状态机只接受置信度不低于 `0.60` 的五类目标。默认至少需要 3 个检测帧支持，并使用支持帧计数的中位值，不会把每帧重复相加。

### 5.7 视觉原始接口

```text
/usb_cam/image_raw                 sensor_msgs/Image
/usb_cam/camera_info               sensor_msgs/CameraInfo
/yolo_trt_node/detections          vision_msgs/Detection2DArray
/yolo_trt_node/annotated           sensor_msgs/Image
/vision/detections                 nuedc_ground_air/Detection2D
/vision/summary                    std_msgs/String(JSON)
```

`Detection2D.msg`：

```text
Header header
string class_name
float32 confidence
float32 center_x
float32 center_y
float32 width
float32 height
```

#### 5.7.1 实验性视觉目标

```text
话题：/mission/vision_goal
类型：geometry_msgs/PoseStamped
frame_id：base_link
默认状态：关闭，不创建发布器
```

`/vision/detections`、`/vision/summary` 和 `/vision/grid_result` 始终按原流程工作，不受该开关影响。只有显式设置 `publish_vision_goal:=true` 后，视觉适配器才会在同类别目标通过 3/5 帧确认后尝试发布目标。默认还会执行 `2.0 s` 发布冷却，并将同类别、中心距离小于 `60 px` 的目标在本次视觉进程中只发布一次。

该消息中的 x/y 是根据检测框相对画面中心得到的有限步长，占位范围默认为前后 `±0.20`、左右 `±0.10`。它没有经过相机内参、目标距离、地面投影和相机到 `base_link` 外参标定，**不能解释为真实米制目标位置，也不能直接用于实机追踪**。完成标定和距离估计前，飞行执行器不得订阅或执行此话题。

### 5.8 飞控遥测接口

现有 `fc_state_bridge.py` 只读遥测，不下发控制：

```text
输入：/mavros/state                 mavros_msgs/State
输入：/mavros/battery               sensor_msgs/BatteryState
输入：/mavros/local_position/pose   geometry_msgs/PoseStamped
输出：/drone/state                  nuedc_ground_air/DroneState
```

`DroneState.msg`：

```text
Header header
string mode
float32 battery_percent
float32 altitude_m
float32 yaw_deg
bool armed
bool connected
```

超过 3 秒没有新的 MAVROS 状态时，`/drone/state.connected` 会变为 false。

## 7. 飞控、电机、电调和机载电脑接线要求

### 7.1 NX 与飞控

之前曾通过 CP2102N 出现 `/dev/ttyUSB0`，但测试多个波特率时串口接收字节为 0。这表示“系统能看到 USB 串口”，不表示 MAVLink 已连通。必须优先排查：

1. 飞控 TX 接适配器 RX，飞控 RX 接适配器 TX，GND 共地。
2. 确认是 TTL 电平而不是 RS-232 电平。
3. 确认飞控端口已启用 MAVLink，并确认对应波特率。
4. 确认端口供电和飞控状态正常。
5. 优先使用稳定的 `/dev/serial/by-id/...`，不要永久硬编码易变化的 `/dev/ttyUSB0`。
6. 用户 `w` 应属于 `dialout` 组。

检查命令：

```bash
ls -l /dev/serial/by-id/ 2>/dev/null
ls -l /dev/ttyUSB* /dev/ttyACM* 2>/dev/null
groups
rostopic echo /mavros/state
```

只有 `/mavros/state.connected: True` 且状态稳定，才能进行下一阶段。

### 7.2 电机和电调

1. 电机、电调必须由飞控输出控制，不能由 NX GPIO 直接产生飞行控制信号。
2. 核对飞控输出编号、机架电机编号、旋向和桨叶方向。
3. 根据电调协议完成校准或配置；DShot 通常不做传统油门行程校准。
4. 检查每个电调的持续电流和峰值电流有足够余量。
5. 拆桨后逐个测试电机编号和旋向。
6. 设置失控保护、低电压保护、姿态异常保护和人工接管。
7. NX 不应通过 USB 给电机系统供电；应使用可靠的稳压 BEC，并处理好共地和电磁干扰。

### 7.3 激光笔

1. 激光笔必须机械固定为垂直向下。
2. 不要用 Jetson GPIO 直接驱动超过引脚能力的激光模块，应使用 MOSFET/光耦/继电器驱动并共地。
3. 默认上电关闭。
4. 只在任务飞行阶段开启；降落、失联、ABORT、飞控未解锁时必须关闭。
5. 必须满足现场人员和眼睛安全要求，测试时不得指向人员。

## 8. 定位和高度保持是当前最大前置条件

本项目目前不假设已经有 GPS、VIO 或室内定位。仅靠 IMU 无法在 4.5m×3.5m 场地内长期保持 50cm 网格精度。

飞控负责人必须提供稳定的本地位置：

- `x/y`：推荐光流+测距、VIO、动捕或其他可验证的室内定位。
- `z`：推荐向下测距传感器配合飞控 EKF，确保在 1.2m 附近稳定。
- yaw：必须有稳定航向，并在起飞点完成地图方向对齐。

验收前至少记录 2～3 分钟 `/mavros/local_position/pose`：无人机静止时位置不能明显漂移，手动移动 0.5m 时坐标变化方向和数量级必须与网格定义一致。

## 9. 建议实现的飞行执行节点

建议新增独立节点，例如：

```text
flight_path_executor.py
```

不要修改地面规划器或视觉状态机来直接控制飞控。执行节点负责 ROS 任务接口与具体 PX4/ArduPilot 控制接口之间的转换。

推荐状态机：

```text
IDLE
  -> PREFLIGHT
  -> TAKEOFF
  -> FOLLOW_PATH
  -> WAIT_GRID_RESULT
  -> FOLLOW_PATH ...
  -> RETURN_HOME
  -> LAND
  -> COMPLETED
```

任意状态都必须能进入：

```text
ABORTED / ERROR / MANUAL_OVERRIDE
```

建议 ROS 参数初值（必须现场调参，不是无条件最终值）：

```yaml
path_topic: /mission/global_path
command_topic: /mission/command
forbidden_topic: /mission/forbidden_zones
grid_topic: /current_grid
grid_state_topic: /vision/grid_state
mission_state_topic: /mission/state
cruise_altitude: 1.2
xy_tolerance: 0.08
z_tolerance: 0.08
arrival_speed_tolerance: 0.10
stable_time: 0.30
cruise_speed: 0.25
setpoint_rate: 20.0
state_timeout: 3.0
dry_run: true
```

执行逻辑要求：

1. `/mission/global_path` 只缓存，不自动执行。
2. 路径必须非空、`frame_id=mission`、首尾都是 A9B1、默认 z 为 0、所有四元数为单位四元数；相邻发布点必须共 x 或共 y，允许同一直线跨多格。
3. 同时订阅禁飞区并二次验证路径不含禁飞格。
4. 只响应最新一次有效路径；避免重启后执行 ROS latch 中残留的旧路径。
5. 收到 `START` 后先进行飞控连接、定位、模式、电池、RC 接管和视觉启动检查。
6. 起飞到 1.2m 并稳定后，先识别起点 A9B1。
7. 每个新方格必须到达中心并稳定，发布 `/current_grid`，等待本格 `GRID_COMPLETE` 后再继续。
8. 重复经过已扫描格时可以直接通过，但仍不能切角进入禁飞格。
9. 对压缩直线段按 `0.5 m` 重建经过格；在 90° 转弯处必须到达拐点后再转向下一段，不能由轨迹平滑器切成斜线。
10. 最后一个点回到 A9B1，确认位置后降落。
11. 完成、异常、人工接管时发布 `/mission/state`。
12. 通信、定位或控制状态超时必须进入安全策略，不能继续盲飞。

如果使用 PX4 OFFBOARD，必须遵守其 setpoint 预发送和持续发送频率要求；如果使用 ArduPilot，应使用对应 GUIDED/任务接口。必须先确认固件，不能把 PX4 和 ArduPilot 的模式、服务名和启动文件混用。

## 10. 时间预算

无禁飞区时，理论覆盖路线约 64 段，每段 0.5m，总平移距离约 32m。每格视觉窗口约：

```text
稳定等待 0.3s + 识别 1.0s = 1.3s
63 格约 81.9s
```

300s 总时限下，剩余约 218s 用于起飞、移动、转弯、回程和降落。理论平均平移速度下限约 `0.15m/s`；建议初始巡航速度约 `0.25m/s`，稳定后再逐步测试到 `0.30～0.35m/s`。不能为了速度牺牲高度、禁飞区和到格稳定性。

## 11. 安全与测试顺序

必须按以下顺序推进：

### 阶段 A：纯软件/无飞控输出

- 运行单元测试验证坐标换算。
- 验证路径首尾、相邻距离、禁飞格和重复格逻辑。
- 用模拟 `/current_grid` 验证按格识别握手。
- 执行节点保持 `dry_run=true`，绝不调用解锁或模式切换。

### 阶段 B：MAVROS 遥测，拆桨

- 确认 `/mavros/state.connected=True`。
- 检查电池、本地位置、高度和 yaw。
- 拆桨验证电机编号、旋向和急停。
- 验证 RC 可随时接管。

### 阶段 C：SITL

- 在 PX4/ArduPilot 对应 SITL 中完整走通 START、起飞、路径、按格握手、返航、降落和 ABORT。
- 人为断开定位、MAVLink 和 ROS，验证失效保护。

### 阶段 D：有限实机飞行

- 空旷防护场地，设置围挡/安全绳，低速单格和两格测试。
- 验证 0.5m 位移、1.2m 高度、90° 拐点和不切角。
- 再逐步扩大到完整 9×7 场地。

任何带桨测试必须由现场飞控负责人明确批准并有人持遥控器监护。

## 14. 可直接交给 AI 的任务指令

下面内容可原样复制给负责飞控开发的 AI：

---

你现在负责一个 ROS 1 Noetic 多旋翼无人机巡查项目的“飞控执行层”。请先完整阅读本文件，不要修改已经完成的地面站、路径规划和视觉统计逻辑，除非发现明确接口错误并先说明。

最重要的安全限制：在我明确确认飞控型号、固件、定位来源、电机电调配置并授权实机测试之前，禁止解锁飞控，禁止下发电机输出，禁止带桨测试。先使用只读检查、dry-run、mock 和 SITL。必须保留 RC 人工接管和硬件急停。

你的目标是实现一个独立、参数化的飞行执行节点，订阅 `/mission/global_path`、`/mission/command`、`/mission/forbidden_zones` 和 `/vision/grid_state`，发布 `/current_grid` 与 `/mission/state`，把现有规划路径安全转换为具体飞控的飞行行为。不要收到 Path 就自动起飞；只有收到 START 且预检全部通过才允许进入执行状态。实验性的 `/mission/vision_goal` 默认关闭，在完成相机标定、距离估计和坐标变换前禁止用于实机控制。

任务参数：9×7 方格，单格 0.5m；A9B1 为起终点和 `mission` 原点；格子到路径坐标为 `x=(B-1)*0.5, y=(9-A)*0.5, z=0`，飞行高度由执行端统一设置为 `takeoff_height=1.2m` 并保持 1.20±0.10m。发布路径会压缩直线中间点，执行端必须沿单轴直线运动并按 0.5m 重建经过格；不能斜飞或在拐角切角；必须避开禁飞格；最后返回 A9B1 降落；总时间不超过 300s。

每到一个新方格并稳定后，发布一次 `/current_grid`（std_msgs/String，如 `A6B3`），然后等待 `/vision/grid_state` 中同一个 grid 的状态变为 `GRID_COMPLETE` 再继续。重复格收到 `GRID_ALREADY_SCANNED` 可继续通过。不得持续按帧累计识别结果。

请按以下顺序工作并汇报证据：

1. 只读检查硬件、飞控固件、串口、MAVLink、MAVROS、定位和现有 ROS 图；列出未知项，不要猜。
2. 修通 `/mavros/state.connected=True`，但暂不发送控制命令。
3. 验证本地坐标方向、高度和漂移，完成 `mission` 到飞控本地坐标系的对齐方案。
4. 设计执行状态机、超时、人工接管、ABORT 和故障保护。
5. 编写带 `dry_run:=true` 默认值的执行节点及自动测试。
6. 对路径进行二次验证：frame_id、首尾、默认 z=0、单位四元数、同轴直线段、重建中间格、禁飞格和旧 latch 路径。
7. 用 mock/SITL 跑通起飞、逐格、视觉握手、返航、降落和异常流程。
8. 只有获得明确授权后才进入拆桨台架和分阶段实飞。

实现时不要混用 PX4 OFFBOARD 与 ArduPilot GUIDED 接口；先识别真实固件，再选择正确 MAVROS 启动文件、模式、服务和 setpoint 话题。所有话题名、容差、速度、超时和串口参数必须可通过 ROS 参数或 launch 配置，禁止硬编码现场 IP、个人路径或不确定硬件值。

每次修改后说明：改了哪些文件、为什么改、如何验证、仍有哪些风险。不得用“代码已运行”代替飞行安全验收。
